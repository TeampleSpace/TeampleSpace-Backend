# 2단계 자료 구현 인계

2026년 11월 19일 기준

## 범위

PDF 업로드와 원본 보관, 본문 추출과 쪽수, 링크 수집, 마크다운 자료와 팀 메모, 목록과 검색, 이름 변경과 삭제, 원문 조회, 작업 조회와 취소 및 재시도를 구현했다
발표 구성, 디자인 설정, PPT 생성과 편집은 이번 범위가 아니다
추출한 본문과 발췌는 제공하지만 외부 요약 모델을 연결하지 않아 summary는 비어 있다

## 작업 위치와 반영 순서

- 원래 Backend 작업 디렉터리와 8081 서버는 변경하지 않았다
- 최신 작업은 stage2-backend의 feat/#36에 있다
- 작업 큐 이슈 33과 PR 38, 자료와 메모 이슈 34와 PR 39, PDF 이슈 35와 PR 40은 main에 병합했다
- 링크 수집은 이슈 36의 기존 브랜치에서 이어서 작업했다
- 링크 연결은 검사한 DNS 주소에 고정한다. 원래 호스트의 TLS 인증과 Host 헤더를 유지하고 리다이렉트마다 다시 검사한다
- 저장소별 이슈 번호를 다른 저장소의 번호로 해석하지 않는다

## 검증 구분

### 실제 실행 서버

기존 8085 서버의 구현 커밋 c926d75에 실제 MySQL과 HTTP 요청을 보내 scripts/verify-materials.py의 32개 검사를 통과했다
실제 PDF는 experiments/export/output/presentation.pdf를 사용했고 링크는 https://example.com/을 수집했다
PDF 원본의 SHA-256 일치와 부분 다운로드, 쪽수와 발췌, 재조회, 메모 개정과 버전 충돌, 팀 메모 저장, 검색, 중복 요청, 링크 실패와 재시도, 작업 취소와 이력, 작성자 및 소유자 삭제 권한, 외부인 거절과 제거된 팀원의 접근 회수를 확인했다
새 QA 계정과 프로젝트만 생성했다. 기존 사용자 데이터와 DB를 초기화하지 않았다

프론트 실제 브라우저에서도 이메일 코드 로그인, PDF 업로드와 분석 완료, 링크 추가와 원문, 마크다운 작성과 미리보기 및 수정, 팀 메모 저장 후 새로고침, PDF 쪽 이동과 전체 보기 후 작업 복귀를 확인했다
메일은 로컬 SMTP 수신기이며 외부 메일함과 소셜 로그인 왕복 검증이 아니다

### 최신 수정 커밋

중단된 실행을 무조건 반복하지 않고 기존 서버를 유지했다
실행 환경이 Java 소켓 연결을 차단해 최신 수정으로 별도 로컬 서버를 띄우지 못했다
Java 21 직접 컴파일을 통과했으며 최신 동작 테스트는 GitHub Actions에서 MySQL 8.4와 실제 HTTP 서버로 실행한다
외부 웹 수집 성공과 실패는 위의 기존 실행 서버에서 확인했다. 최신 DNS 고정은 CI의 실제 로컬 HTTP 서버와 대체 DNS 응답으로 검증한다
CI의 메일 및 일부 외부 분석 입력은 테스트 대역이다

## 재검증

로컬 검증 서버와 .eml 파일을 저장하는 SMTP 수신기를 실행한 뒤 다음 명령을 사용한다
메일 인증과 가입에 사용할 검증 약관 버전은 local-v1이며 운영 설정을 변경해서 실행하지 않는다

```sh
VERIFY_API_URL=http://127.0.0.1:8085 \
VERIFY_FRONTEND_ORIGIN=http://localhost:5181 \
VERIFY_MAIL_DIR=/검증용/메일/폴더 \
python3 scripts/verify-materials.py
```

이 스크립트는 루프백 API 주소만 허용하고 매번 새 QA 데이터를 만든다
정규 테스트는 compose.yaml의 MySQL을 준비한 뒤 ./gradlew build로 실행한다

## 남은 운영 설정

- 운영 파일 저장소와 수명 및 정리 정책, 백업
- 요약 모델 제공자와 키, 비용 및 입력 보관 정책
- 배포 환경의 외부 요청 제한과 네트워크 정책
- 실제 소셜 제공자 로그인과 운영 메일 수신은 이번 변경에서 재검증하지 않았다

로컬 실행 포트는 기존 8081, 8085 백엔드와 5176, 5180 프론트를 보존했다
이번 실제 브라우저 검증 프론트는 5181이며 8085로 프록시한다
8086은 최신 서버 실행을 시도했지만 Java DB 연결 제한으로 종료됐다
