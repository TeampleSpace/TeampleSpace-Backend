# 0단계 결과

개발 순서 0단계에서 백엔드가 한 일, 실제로 확인한 것, 사람의 확인이 필요한 것을 구분해 적는다.
기준은 노션의 개발 순서와 1차 출시 기준이며 2026-11-18에 다시 읽어 0단계 내용이 이전과 같음을 확인했다.

## 범위

- 공통 계약, 공통 오류 처리, 저장과 이력과 이벤트 규칙의 검증, 파일 출력 실험, 재현 가능한 빌드와 테스트까지다
- 배포는 이번 종료 조건에서 뺐다. 배포 환경과 파일 저장소를 만들지 않았고 운영 설정도 하지 않았다. 아래 후속 준비 사항에 적는다
- 인증, 프로젝트, 운영용 편집 API, 완성된 내보내기는 이후 단계다

### 따로 확인한 것

- 서버를 실제로 띄워 없는 경로를 호출했다. 404와 공통 오류 형식으로 응답했고 응답 헤더와 본문의 요청 식별자가 같았다
- 주소를 해석할 수 없는 요청은 서블릿 컨테이너가 먼저 거절해 공통 오류 형식이 아닌 400이 왔다. 고치지 않았다
- 프론트에서 쓰는 ajv 8로 스키마와 예제 38개를 검증해 백엔드 테스트와 같은 결과가 나왔다
- 스냅샷 읽기의 격리 수준을 일부러 낮추면 스냅샷 일관성 시험이 실패했다
- 문서 예제의 글자를 바꾸면 산출물 일치 시험이 실패했다
- Pretendard 글꼴 폴더를 없는 경로로 지정하면 출력 실험 생성 시험 1개가 건너뛰어졌다

### CI

GitHub Actions에서 `compose.yaml`의 MySQL 8.4로 `./gradlew build`를 돌린다.

- PR 6, 7, 8, 9, 10, 12는 PR의 CI와 머지 뒤 main의 CI가 통과했다
- PR 16과 17의 CI는 통과했다
- CI에는 Pretendard가 없어 출력 실험 생성 시험 1개는 건너뛴다

### 실행하지 않은 것

- 프론트와 실제 서버를 연결한 확인. 열려 있는 `/v1` 경로가 없다
- 배포 환경에서의 실행
- 설계서 검증 계획의 인증, 업로드, 작업, 결제 관련 시험. 해당 기능이 아직 없다
- 부하, 복구, 백업 시험

## 프론트 인계

- 기준은 `contracts` 폴더다. 프론트는 `fb919ee` 시점의 복사본을 쓰고 있다
- 그 뒤 달라진 내용과 프론트가 확인할 것은 `contracts/CHANGELOG.md`에 있다
- 계약 기준 커밋은 PR 16과 17이 머지된 뒤의 main이다. 머지 전에는 `feat/#13`과 `feat/#14` 브랜치의 내용이다
- 프론트 저장소는 수정하지 않았다
- 이 저장소의 기준은 설계서와 구현으로 백엔드가 정리한 것이다. 프론트가 반영해 확인하기 전에는 합의로 적지 않는다

프론트가 다시 복사한 뒤 볼 것은 다음과 같다.

- 이벤트 형식의 필수 항목이 늘었다
- 요청 오류도 공통 오류 형식으로 온다
- CSRF 헤더 이름, 이벤트 누락 판단, 다시 연결하는 순서, 묶음 종료 주체가 기준으로 적혔다
- 오류 목록의 `decided`가 `basis`로 바뀌었다

## 후속 준비 사항

배포를 진행하기로 하면 필요한 것이다. 지금은 아무것도 만들지 않았다.

- 배포 환경과 운영 MySQL 8.4. 서버 계정, 마이그레이션 계정, 백업 계정을 나눈다
- 비공개 파일 저장소와 최소 권한 접근 키
- 운영 환경변수. `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`와 마이그레이션 계정용 값
- 프론트와 같은 사이트에서 `/v1`을 넘겨주는 프록시 구성과 이벤트 구독을 위한 버퍼링 해제
- 컨테이너가 거절하는 요청의 응답 형식
- PDF를 만들 서버의 글꼴 파일과 사용 권한 확인
- 배포 경로를 CI에 잇는 일
- 메일, 소셜 로그인, AI 제공자 계정과 약관 문서 주소
