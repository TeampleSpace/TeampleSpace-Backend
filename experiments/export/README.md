# PPTX와 PDF 출력 실험

내부 슬라이드 데이터를 실제 PPTX와 PDF 파일로 만들 수 있는지 확인한 실험이다.
사용자용 내보내기 API, 작업 화면, 다운로드는 이후 단계에서 만든다.

실행일은 2026-11-18, 환경은 macOS와 Java 21이다.

## 입력

프론트와 함께 쓰는 문서 예제 `contracts/examples/presentation.json` 하나를 그대로 쓴다.
한글, 긴 문장, 개행, 사각형, 둥근 사각형, 원, 이미지와 자르기, 회전, 출처 문구가 들어 있다.

## 방식

| 항목 | 내용 |
| --- | --- |
| 단위 | 캔버스 1px을 0.75pt로 본다. 1280x720 캔버스가 960x540pt 슬라이드와 페이지가 된다 |
| PPTX | Apache POI로 글상자, 도형, 그림을 만든다. 줄 간격은 포인트 고정 값으로 적는다 |
| PDF | Apache PDFBox로 문서 좌표에 직접 그린다. 줄바꿈은 코드에서 계산하고 글꼴은 쓰인 글자만 파일에 넣는다 |
| 글꼴 굵기 | PowerPoint는 굵기를 숫자로 받지 못한다. 400은 보통, 700은 굵게로 적고 그 밖의 굵기는 `Pretendard Medium`처럼 글꼴 이름으로 고른다 |
| 줄바꿈 | PDF는 띄어쓰기에서 줄을 바꾸고 한 줄보다 긴 낱말만 글자 단위로 나눈다. PPTX는 보는 프로그램이 정한다 |

코드는 `src/test/java/com/teamplespace/export`에 있다. 실험 단계라 테스트 쪽에 두었고 운영 코드에는 포함되지 않는다.

## 다시 실행하는 방법

```bash
./gradlew test --tests '*ExportExperimentTests' --rerun
```

결과는 `build/export-experiment`에 생긴다.

- Pretendard 글꼴 파일이 `~/Library/Fonts`에 있어야 한다. 다른 폴더에 있으면 `EXPORT_FONT_DIR` 환경변수로 알려 준다
- 글꼴 파일이 없으면 이 실험은 건너뛴다. CI에는 글꼴이 없어 건너뛴다
- macOS 훑어보기 그림은 `qlmanage -t -s 1280 -o 폴더 build/export-experiment/pptx-slide-1.pptx`로 만든다
- PowerPoint에서 PPTX를 열어 PDF로 내보낸 파일을 `build/export-experiment/powerpoint-export.pdf`로 두고 다시 실행하면 비교용 그림이 생긴다

## 산출물

`output` 폴더에 이번 실행 결과를 넣어 두었다.

| 파일 | 내용 |
| --- | --- |
| `presentation.pptx` | 만든 PPTX |
| `presentation.pdf` | 만든 PDF |
| `pdf-page-1.png`, `pdf-page-2.png` | 만든 PDF를 그린 그림 |
| `powerpoint-page-1.png`, `powerpoint-page-2.png` | PowerPoint 16.113.3이 PPTX를 열어 내보낸 PDF를 그린 그림 |
| `quicklook-slide-1.png`, `quicklook-slide-2.png` | macOS 훑어보기가 PPTX를 그린 그림 |

## 확인한 결과

### 열림 여부

- PPTX는 Mac용 PowerPoint 16.113.3에서 열렸다. 슬라이드 2장, 도형 4개와 8개로 읽혔고 PDF로 내보낼 수 있었다
- PPTX를 POI로 다시 열어 슬라이드 수, 도형 수, 글자, 자르기 값을 확인했다
- PDF를 PDFBox로 다시 열어 2쪽, 960x540pt, 글꼴 내장을 확인했다. macOS 훑어보기로도 열렸고 첫 쪽이 같은 모습이었다
- PDF의 글자는 도형이 아니라 글자로 들어가 선택하고 검색할 수 있다. 한글 문장을 그대로 추출했다

### 항목별 비교

| 4 | 어려움으로 꼽았습니다. | 어렵다는 점을 두 번째 어려움으로 꼽았습니다. |

### 예제와 다르게 나온 점

- PPTX는 글꼴을 파일에 담지 않는다. 보는 PowerPoint가 그 글꼴을 쓰지 못하면 다른 글꼴로 바뀌고 글자 폭이 달라져 줄바꿈과 제목 너비가 달라진다. 이번 실행에서 실제로 그렇게 됐다
- 같은 PPTX라도 보는 프로그램에 따라 한글 줄바꿈 규칙이 다르다. PowerPoint는 낱말 단위, macOS 훑어보기는 글자 단위였다
- macOS 훑어보기는 글상자 회전을 그리지 않는다
- 출처 연결 정보는 파일에 들어가지 않는다. 예제의 출처 문구는 일반 글자 요소라서 보일 뿐이다
- 이미지 대체 문구는 PPTX에만 적었다. PDF에는 넣지 않았다
- POI의 슬라이드 그리기 기능으로 PPTX를 그림으로 만들면 글자와 이미지가 180도 돌아간 채로 나왔다. 파일 자체는 정상이다. 그래서 POI 그리기를 PDF 변환이나 미리보기에 쓰지 않고 PDF를 직접 그리는 방식을 택했다

## 확인하지 못한 것

- Windows용 PowerPoint, 웹용 PowerPoint, Keynote, Google 슬라이드에서의 표시
- 이 맥의 PowerPoint가 설치된 Pretendard를 쓰지 않은 이유. 글꼴은 사용자 글꼴 폴더에 설치돼 있고 훑어보기는 그 글꼴로 표시했다
- PowerPoint에서 글자를 고친 뒤 다시 저장했을 때의 결과
- PowerPoint에서 이미지 대체 문구가 보이는지
- Acrobat이나 브라우저 같은 다른 PDF 뷰어에서의 표시와 인쇄 결과
- POI 그리기 결과가 뒤집히는 원인
- 슬라이드와 요소가 많은 문서의 처리 시간과 메모리

## 라이브러리와 실행 조건

| 이름 | 버전 | 라이선스 | 쓰임 |
| --- | --- | --- | --- |
| Apache POI poi-ooxml | 6.0.0 | Apache License 2.0 | PPTX 생성 |
| Apache PDFBox | 3.0.8 | Apache License 2.0 | PDF 생성과 확인용 그림 |
| Pretendard | 설치된 글꼴 파일 | SIL Open Font License 1.1 | 예제의 글꼴. 저장소에는 넣지 않았다 |

- 두 변환 모두 서버 JVM 안에서 실행된다. 별도 프로그램을 띄우지 않으므로 이 방식만으로는 변환용 프로세스를 따로 둘 이유가 생기지 않는다
- PDF를 만들려면 서버에 굵기별 글꼴 파일이 있어야 한다. 글꼴에 없는 글자가 오면 변환이 실패하므로 대체 글꼴 처리가 필요하다
- PPTX는 글꼴 파일 없이 만들 수 있지만 보는 컴퓨터에 그 글꼴이 있어야 같은 모습이 된다
- 이미지 읽기와 확인용 그림 생성은 Java의 화면 없는 그래픽 기능을 쓴다

## 지원 제한

- 스타일은 요소 단위만 다룬다. 글자 범위별 스타일은 문서 형식에 없다
- 글자의 세로 정렬은 위쪽 고정이다
- 이미지는 PNG만 시험했다
- PDF에는 대체 문구, 링크, 문서 구조 정보가 없다
- 슬라이드 노트, 애니메이션, 표, 차트는 다루지 않는다

## 다음에 정해야 할 것

- 슬라이드에서 쓸 수 있는 글꼴과 PowerPoint에서 그 글꼴이 없을 때의 정책. 글꼴이 바뀌면 줄바꿈이 달라진다
- 한글 줄바꿈 규칙. 편집기, PDF, PowerPoint가 같은 규칙을 쓰도록 낱말 단위와 글자 단위 중 하나를 문서 형식에 정해야 한다
- 출처 연결을 파일에 표시하는 방식
- 내보내기 형식을 지원한다고 공개하는 기준. 지금 결과로는 PDF는 예제대로 나오지만 PPTX는 보는 환경의 글꼴에 따라 달라지므로 두 형식을 모두 지원한다고 기록하지 않는다
