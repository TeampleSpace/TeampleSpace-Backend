# PPTX와 PDF 출력 실험

내부 슬라이드 데이터를 실제 PPTX와 PDF 파일로 만들 수 있는지 확인한 실험이다.
사용자용 내보내기 API, 작업 화면, 다운로드는 이후 단계에서 만든다.

실행일은 2026-11-18, 환경은 macOS와 Java 21이다.

## 입력

프론트와 함께 쓰는 문서 예제 `contracts/examples/presentation.json` 하나를 그대로 쓴다.
한글, 긴 문장, 개행, 사각형, 둥근 사각형, 원, 이미지와 자르기, 회전, 출처 문구가 들어 있다.

| 파일 | SHA-256 앞 16자리 |
| --- | --- |
| `contracts/examples/presentation.json` | `81020c2c41a64dca` |
| `contracts/examples/assets/0193a000-0000-7000-8000-0000000000c1.png` | `eb8723bd51fe4ca4` |

- 프론트 저장소의 계약 복사본에 있는 문서 예제도 같은 해시다. 2026-11-18에 확인했다
- `output` 폴더의 PPTX와 PDF에 이 예제의 글자가 모두 들어 있는지는 `ExportExperimentTests`가 확인한다. 예제를 고치고 산출물을 다시 만들지 않으면 이 테스트가 실패한다

## 방식

| 항목 | 내용 |
| --- | --- |
| 단위 | 캔버스 1px을 0.75pt로 본다. 1280x720 캔버스가 960x540pt 슬라이드와 페이지가 된다 |
| PPTX | Apache POI로 글상자, 도형, 그림을 만든다. 줄 간격은 포인트 고정 값으로 적는다 |
| PDF | Apache PDFBox로 문서 좌표에 직접 그린다. 줄바꿈은 코드에서 계산하고 글꼴은 쓰인 글자만 파일에 넣는다 |
| 글꼴 굵기 | PowerPoint는 굵기를 숫자로 받지 못한다. 400은 보통, 700은 굵게로 적고 그 밖의 굵기는 `Pretendard Medium`처럼 글꼴 이름으로 고른다 |
| 줄바꿈 | PDF는 띄어쓰기에서 줄을 바꾸고 한 줄보다 긴 낱말만 글자 단위로 나눈다. PPTX는 보는 프로그램이 정한다 |

코드는 `src/test/java/com/teamplespace/export`에 있다. 실험 단계라 테스트 쪽에 두었고 운영 코드에는 포함되지 않는다.

## 다시 실행하는 방법

```bash
./gradlew test --tests '*ExportExperimentTests' --rerun
```

결과는 `build/export-experiment`에 생긴다.

- Pretendard 글꼴 파일이 `~/Library/Fonts`에 있어야 한다. 다른 폴더에 있으면 `EXPORT_FONT_DIR` 환경변수로 알려 준다
- 글꼴 파일이 없으면 이 실험은 건너뛴다. CI에는 글꼴이 없어 건너뛴다
- macOS 훑어보기 그림은 `qlmanage -t -s 1280 -o 폴더 build/export-experiment/pptx-slide-1.pptx`로 만든다
- PowerPoint에서 PPTX를 열어 PDF로 내보낸 파일을 `build/export-experiment/powerpoint-export.pdf`로 두고 다시 실행하면 비교용 그림이 생긴다

## 산출물

`output` 폴더에 이번 실행 결과를 넣어 두었다.

| 파일 | 내용 |
| --- | --- |
| `presentation.pptx` | 만든 PPTX |
| `presentation.pdf` | 만든 PDF |
| `pdf-page-1.png`, `pdf-page-2.png` | 만든 PDF를 그린 그림 |
| `powerpoint-page-1.png`, `powerpoint-page-2.png` | PowerPoint 16.113.3이 PPTX를 열어 내보낸 PDF를 그린 그림 |
| `quicklook-slide-1.png`, `quicklook-slide-2.png` | macOS 훑어보기가 PPTX를 그린 그림 |

## 확인한 결과

### 열림 여부

- PPTX는 Mac용 PowerPoint 16.113.3에서 열렸다. 슬라이드 2장, 도형 4개와 8개로 읽혔고 PDF로 내보낼 수 있었다
- PPTX를 POI로 다시 열어 슬라이드 수, 도형 수, 글자, 자르기 값을 확인했다
- PDF를 PDFBox로 다시 열어 2쪽, 960x540pt, 글꼴 내장을 확인했다. macOS 훑어보기로도 열렸고 첫 쪽이 같은 모습이었다
- PDF의 글자는 도형이 아니라 글자로 들어가 선택하고 검색할 수 있다. 한글 문장을 그대로 추출했다

### 항목별 비교

기준은 문서 예제의 좌표와 내용이다.

| 항목 | PDF | PPTX를 PowerPoint로 열었을 때 | PPTX를 macOS 훑어보기로 열었을 때 |
| --- | --- | --- | --- |
| 한글 표시 | 표시됨 | 표시됨 | 표시됨 |
| 글꼴 | Pretendard가 파일에 들어가 그대로 보인다 | Pretendard 대신 맑은 고딕과 Calibri로 보였다 | Pretendard로 보였다 |
| 긴 문장 줄바꿈 | 낱말 단위 4줄 | 낱말 단위 4줄이지만 글자 폭이 넓어져 줄이 나뉘는 자리가 다르다 | 글자 단위로 나뉘어 낱말 중간에서 줄이 바뀐다 |
| 개행 | 개행대로 줄이 나뉜다 | 같음 | 같음 |
| 줄 간격 | 예제와 같다 | 예제와 같다 | 예제와 같다 |
| 사각형, 원 | 예제 위치와 크기대로 | 같음 | 같음 |
| 둥근 모서리 | 반영 | 반영 | 반영 |
| 이미지와 자르기 | 반영 | 반영 | 반영 |
| 회전 | 반영 | 반영. 352도로 읽힌다 | 글상자 회전이 반영되지 않고 바로 선 채로 보인다 |
| 굵기 500 | Pretendard Medium으로 보인다 | 글꼴이 바뀌어 보통 굵기로 보인다 | 반영 |
| 출처 문구 | 글자 요소로 그대로 보인다 | 같음 | 같음 |

긴 문장이 실제로 나뉜 자리는 다음과 같다. 편집 화면 기준은 프로젝트 루트의 `Docs/fe/output-comparison.md`에 적힌 2026-11-18 측정값이다.

| 줄 | 편집 화면 기준 | PDF | PowerPoint |
| --- | --- | --- | --- |
| 1 | 설문에 참여한 대학생 가운데 다수는 발표 자료를 만들 때 각자 작업한 내 | 설문에 참여한 대학생 가운데 다수는 발표 자료를 만들 때 각자 작업한 | 설문에 참여한 대학생 가운데 다수는 발표 자료를 만들 때 각자 |
| 2 | 용을 마지막에 한꺼번에 합치는 과정에서 가장 많은 시간을 쓴다고 답했 | 내용을 마지막에 한꺼번에 합치는 과정에서 가장 많은 시간을 쓴다고 | 작업한 내용을 마지막에 한꺼번에 합치는 과정에서 가장 많은 |
| 3 | 으며, 누가 어떤 부분을 고쳤는지 확인하기 어렵다는 점을 두 번째 어려움 | 답했으며, 누가 어떤 부분을 고쳤는지 확인하기 어렵다는 점을 두 번째 | 시간을 쓴다고 답했으며, 누가 어떤 부분을 고쳤는지 확인하기 |
| 4 | 으로 꼽았습니다. | 어려움으로 꼽았습니다. | 어렵다는 점을 두 번째 어려움으로 꼽았습니다. |

편집 화면은 글자 단위, PDF는 낱말 단위, PowerPoint는 낱말 단위이면서 글꼴이 바뀌어 폭이 다르다. 세 곳 모두 네 줄이지만 나뉘는 자리가 서로 다르다.

### 편집 화면 기준 이미지와의 비교

프로젝트 루트의 기준 이미지 `Docs/fe/reference/slide-1.png`, `slide-2.png`와 `output`의 PDF 그림을 같은 크기 1280x720에서 픽셀 단위로 견주었다. 기준 이미지는 프론트 커밋 `b12e768`의 것이다. 색 차이가 큰 픽셀만 셌다.

| 슬라이드 | 다른 픽셀 | 어디가 다른가 |
| --- | --- | --- |
| 1 | 전체의 0.81% | 모두 글자 영역이다. 글자가 없는 제목 띠 부분은 차이가 없다 |
| 2 | 전체의 2.66% | 3분의 2가 줄바꿈이 다른 긴 본문이다. 원은 차이가 없고 둥근 사각형과 이미지 영역은 가장자리에 조금 있다 |

줄바꿈이 같은 글상자에서도 글자 가장자리의 픽셀이 다르다. 글자 위치가 조금 다른 것인지 그리는 방식의 차이인지는 분석하지 않았다. 눈으로 볼 때 위치, 크기, 색, 회전, 겹침 순서는 같았다.

### 예제와 다르게 나온 점

- PPTX는 글꼴을 파일에 담지 않는다. 보는 PowerPoint가 그 글꼴을 쓰지 못하면 다른 글꼴로 바뀌고 글자 폭이 달라져 줄바꿈과 제목 너비가 달라진다. 이번 실행에서 실제로 그렇게 됐다
- 같은 PPTX라도 보는 프로그램에 따라 한글 줄바꿈 규칙이 다르다. PowerPoint는 낱말 단위, macOS 훑어보기는 글자 단위였다
- macOS 훑어보기는 글상자 회전을 그리지 않는다
- 출처 연결 정보는 파일에 들어가지 않는다. 예제의 출처 문구는 일반 글자 요소라서 보일 뿐이다
- 이미지 대체 문구는 PPTX에만 적었다. PDF에는 넣지 않았다
- POI의 슬라이드 그리기 기능으로 PPTX를 그림으로 만들면 글자와 이미지가 180도 돌아간 채로 나왔다. 파일 자체는 정상이다. 그래서 POI 그리기를 PDF 변환이나 미리보기에 쓰지 않고 PDF를 직접 그리는 방식을 택했다

## 확인하지 못한 것

- Windows용 PowerPoint, 웹용 PowerPoint, Keynote, Google 슬라이드에서의 표시
- 이 맥의 PowerPoint가 설치된 Pretendard를 쓰지 않은 이유. 글꼴은 사용자 글꼴 폴더에 설치돼 있고 훑어보기는 그 글꼴로 표시했다
- PowerPoint에서 글자를 고친 뒤 다시 저장했을 때의 결과
- PowerPoint에서 이미지 대체 문구가 보이는지
- Acrobat이나 브라우저 같은 다른 PDF 뷰어에서의 표시와 인쇄 결과
- POI 그리기 결과가 뒤집히는 원인
- 슬라이드와 요소가 많은 문서의 처리 시간과 메모리

## 라이브러리와 실행 조건

| 이름 | 버전 | 라이선스 | 쓰임 |
| --- | --- | --- | --- |
| Apache POI poi-ooxml | 6.0.0 | Apache License 2.0 | PPTX 생성 |
| Apache PDFBox | 3.0.8 | Apache License 2.0 | PDF 생성과 확인용 그림 |
| Pretendard | 설치된 글꼴 파일 | SIL Open Font License 1.1 | 예제의 글꼴. 저장소에는 넣지 않았다 |

- 두 변환 모두 서버 JVM 안에서 실행된다. 별도 프로그램을 띄우지 않으므로 이 방식만으로는 변환용 프로세스를 따로 둘 이유가 생기지 않는다
- PDF를 만들려면 서버에 굵기별 글꼴 파일이 있어야 한다. 글꼴에 없는 글자가 오면 변환이 실패하므로 대체 글꼴 처리가 필요하다
- PPTX는 글꼴 파일 없이 만들 수 있지만 보는 컴퓨터에 그 글꼴이 있어야 같은 모습이 된다
- 이미지 읽기와 확인용 그림 생성은 Java의 화면 없는 그래픽 기능을 쓴다

## 지원 제한

지금 방식으로 만든 파일의 한계다. 사용자에게 내보내기를 열기 전에 알려야 하거나 해결해야 한다.

| 구분 | 제한 |
| --- | --- |
| 글꼴 대체 | PPTX는 글꼴을 파일에 담지 않는다. 보는 PowerPoint가 그 글꼴을 쓰지 못하면 다른 글꼴로 바뀐다. 이번 실행에서 Pretendard가 맑은 고딕과 Calibri로 바뀌었다 |
| 글꼴 대체 | 글꼴이 바뀌면 글자 폭이 달라져 줄이 나뉘는 자리와 제목 너비가 달라진다. 500 같은 중간 굵기는 보통 굵기로 보인다 |
| 글꼴 대체 | PDF는 서버에 굵기별 글꼴 파일이 있어야 만들 수 있다. 글꼴에 없는 글자가 오면 변환이 실패한다 |
| 한글 줄바꿈 | 편집 화면은 글자 단위, PDF는 낱말 단위, PowerPoint는 낱말 단위다. 같은 문서가 화면과 파일에서 다르게 줄바꿈된다 |
| 한글 줄바꿈 | PPTX의 줄바꿈은 여는 프로그램이 계산한다. macOS 훑어보기는 같은 파일을 글자 단위로 나눴다 |
| 출처 표현 | 출처 연결 정보는 PPTX와 PDF 어디에도 들어가지 않는다. 문서에 일반 글자로 적힌 출처 문구만 그대로 옮겨진다 |
| 출처 표현 | 자료가 지워졌는지, 어느 쪽의 어느 대목인지 같은 연결 정보는 파일에서 알 수 없다 |
| 스타일 | 요소 단위 스타일만 다룬다. 글자 범위별 스타일은 문서 형식에 없다. 글자의 세로 정렬은 위쪽 고정이다 |
| 이미지 | PNG만 시험했다. 이미지 대체 문구는 PPTX에만 적고 PDF에는 넣지 않았다 |
| PDF | 대체 문구, 링크, 문서 구조 정보가 없다 |
| 범위 | 슬라이드 노트, 애니메이션, 표, 차트는 다루지 않는다 |
| 미리보기 | POI의 슬라이드 그리기는 글자와 이미지가 180도 돌아가 쓸 수 없다. macOS 훑어보기는 글상자 회전을 그리지 않는다 |

## 후속 과제

| 과제 | 필요한 것 | 시점 |
| --- | --- | --- |
| 슬라이드 글꼴 목록과 대체 정책 | 쓸 수 있는 글꼴, PowerPoint에 글꼴이 없을 때의 안내나 대체 방법을 정한다 | 사용자 결정. 디자인을 만드는 3단계 전 |
| 한글 줄바꿈 규칙 통일 | 낱말 단위와 글자 단위 중 하나를 정하고 편집 화면, PDF, PPTX가 같은 규칙을 쓰게 한다 | 사용자 결정. 편집을 만드는 4단계 전 |
| PPTX에서 줄바꿈 규칙 지정 | 정한 규칙을 PPTX에 적을 수 있는지 확인한다 | 내보내기를 만드는 7단계 |
| 출처 표시 방식 | 각주, 노트, 마지막 장 가운데 무엇으로 표시할지 정한다 | 사용자 결정. 7단계 전 |
| 서버의 글꼴 파일 준비 | 글꼴 사용 권한을 확인하고 서버에 두는 방법을 정한다 | 배포를 준비할 때 |
| 다른 환경 확인 | Windows용과 웹용 PowerPoint, Keynote, 다른 PDF 뷰어에서 열어 본다 | 7단계 |
| PowerPoint에서 편집 후 재저장 | 글자를 고치고 저장한 파일이 정상인지 확인한다 | 7단계 |
| 큰 문서의 처리 시간과 메모리 | 슬라이드와 요소가 많은 문서로 잰다 | 7단계 |
| 내보내기 형식 공개 | 위 과제를 마친 형식만 기능 지원 정보에 넣는다. 지금은 비워 두었다 | 7단계 |

완성된 내보내기 API, 작업 처리, 다운로드는 7단계에서 만든다. 이 실험의 코드는 테스트 쪽에 있고 운영 코드에 포함되지 않는다.
